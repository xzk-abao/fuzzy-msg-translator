# 示例：功能询问 / 模糊需求场景（同事原话 → 4 件套）

**同事发来的：**

> 导出功能能不能改一下，导出来的表看着不对

---

## ① 卡片（自己看的，不发微信）

```
场景：功能询问/模糊需求
原话：导出功能能不能改一下，导出来的表看着不对
已确认：
  - 对象：导出功能
  - 现象：导出结果"看着不对"（形容词，还没换成例子）
待确认：
  - 例子：哪次导的、导的哪个表、哪一列不对
  - 期望：应该是什么样
  - 定性：bug（导错了）还是需求变更（想要新样式/新字段）
```

## ② 话术（2 步收敛，各 1 轮）

第一轮（要例子）：

```
你说导出来看着不对，上次导的是哪张表？哪列不对，截个图发我
```

第二轮（看对方回复后，二选一定性）：

```
这个字段是本来就该有、导出来没了，还是你想加个新字段？
```

- 对方说"本来就该有"→ 是 bug，转 bug 槽位（哪一列、什么条件下丢的）
- 对方说"想加个新的"→ 是需求变更，接"你希望加哪列？按什么规则取？"

## ③ 回写（槽位问完锁定边界时发）

```
对一下啊：就是导出的客户表里手机号那列空的，你希望按客户档案里的手机号带出来，我按这个改，对吧
```

## ④ 任务记录（转译分析完成立即落，不等回写）

```
| T-002 | 同事B | 需求 | 导出客户表手机号列为空 | P1 | 待确认 | 11-13 | | 待确认：哪次导的/该取哪个源 |
```

优先级判 P1：数据相关。如果对方只要的是"表头颜色改下"，那就是 P2。
