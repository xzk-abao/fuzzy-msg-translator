# fuzzy-msg-translator（微信模糊消息转译器）

## 触发
- 用户贴来一句模糊的对方原话（截图文字、聊天记录），说"帮我转译""帮我问明白""这条怎么回"
- 用户说"帮我看看这个需求怎么问"

## 铁律（违反即失败）
1. **不脑补**。原话里没有的信息，一律进"待确认槽位"，绝不出现在卡片已确认区，绝不写进话术里当事实。
2. **话术里只问 1-2 个问题，不连珠炮**。每轮最多问 2 个槽位，对方回复后再问下一轮。
3. **话术必须是微信人话，不是 AI 话**。标准：念一遍，不像你会发进微信的字句，就重写。硬规则：
   - 拆成 2-3 条短气泡发，别一条长文砸过去
   - **每轮必须有逻辑链：复述 → 猜想 → 提问**。复述=证明听懂了对方的话；猜想=给出你目前的判断；提问的每个信息都要带"为什么问"（拿到这个能判断什么），不裸问。"截两张图发我"是裸问；"截两张图发我，我看下是缓存没刷还是数据没存上"才有逻辑。
   - 能要截图就别让对方打字描述（"截个图发我"比"请描述一下"自然一万倍）
   - 禁用 AI 腔词表：「我理解一下」「我猜可能是」「方便帮我确认一下」「为了确认是哪种」「具体是……的情况」「能否详细描述」「我猜测」——出现任何一词即重写
   - 禁用占位符符号【】，回写时填成具体词（"列表没刷新"而不是"【现象】"）
   - 二选一可以，但用口语："是登不进去，还是进去报错？"不是"是 A 情况还是 B 情况"
   - 逻辑链不等于三段论腔，别写成"首先其次最后"；因果用"你看下是不是""我判断是"这类词自然带出
4. **一次给全**：卡片、话术、回写模板；转译分析完成后立即补第四条——任务记录（初态"待确认"）。话术必须可以直接复制粘贴发进微信（口语、短句、不用 markdown 符号）。

## 流程
1. 让用户（或从粘贴内容）确认：**场景类型** = bug/数据异常 还是 功能询问/模糊需求。不确定就问一句，默认按 bug 处理（"有点问题"类表述多为 bug）。
2. 按对应模板提取槽位，产出三件套。
3. 分析完成后**立即落一条任务到任务记录表**（用户指定位置，初态"待确认"）。动手前先翻任务记录：同一来源 + 现象/位置重合的，合入已有条目改状态，不重复开。
4. 把【话术】单独用代码块包起来，提示用户"这段直接复制发微信"。
5. 提醒：对方回复后，把回复贴回来，再跑一轮，直到所有槽位已确认或对方明确说不清——那时输出回写模板锁定边界。
6. 回写通过 → 该任务改"待排期"；动手修之前按 P0-P2 排序，开修改"进行中"，修完改"待验证"，对方确认好了再"已关闭"。

## 任务记录（闭环）
任务表位置由用户指定（建议：仓库 templates/task-log.md 拷到自己的工作目录，每天翻）。

**时机：需求/bug 一到、完成转译分析后立即记录一条，初态"待确认"——不等回写。之后随进度推进：槽位问完且回写通过=待排期；开修=进行中；修完=待验证；对方确认=已关闭。**

状态机（只允许沿箭头走，跳状态要在备注里写为什么）：
`待确认 → 待排期 → 进行中 → 待验证 → 已关闭`
分支：`待确认/待排期 → 已拒`（对方自己放弃了 / 判定不是问题，原因写备注）

**优先级只按 3 条规则判，不凭感觉：**
- P0：卡住主流程 / 用不了（"我提交不了"）
- P1：数据错 / 钱相关（"统计数字不对"）
- P2：体验类 / 外观（"这个按钮位置别扭"）
判不准就向来源方问一句："这个不处理的话，卡住的是啥事？"——答案填进备注，顺手把优先级定了。

**动手修之前必查：** 翻任务记录，同一来源 + 相似现象 → 合并到已有行改状态，不新开；已有一条"进行中"的 → 提醒用户"这个已在修，编号 T-xxx，别重复接活"。

**不做自动催办。** 要催的时候翻任务记录里状态为"待验证"的行，参考这句人话（仅参考措辞，不自动执行）："上次那个 XX 你那边看下好了没？没好的截图发我，我再跟一下。"

## 模板一：bug / 数据异常
转译目标：把"对不上"拆成 在哪对不上 + 和什么对不上 + 什么条件下对不上。

槽位（按优先级排，前两个没填满不进入话术第二问）：
| 槽位 | 说明 | 追问示例（微信人话，可照搬改） |
|---|---|---|
| 比较两端 | 哪里的数 vs 哪里的数（页面A字段X vs 页面B字段X） | "列表里显示的是旧电话，详情页是新电话，对吧？" |
| 期望值 | 对方认为哪个是对的 | "按说应该显示哪个？" |
| 观察路径 | 刷新后/换账号后/换一条数据后是否仍不一致 | "刷新过吗？换个账号登录看正常不？" |
| 复现条件（可选） | 什么时候开始的、哪次改过 | "什么时候开始的？" |

每轮组合示例（逻辑链：复述 → 猜想 → 提问，拆成 2-3 条气泡发）：
1. "这个大概知道哪的问题，列表还是旧的、详情页是新值？"
2. "截两张图发我，我看下是缓存没刷还是数据没存上"
3. "顺带问下，一直这样还是这两天才这样？"

三条分别干的事：第 1 条证明听懂了（复述+猜想在里面）；第 2 条每个信息都带用途（截图→区分两个猜想）；第 3 条判断是回归故障还是老问题，决定查哪段改动。

## 模板二：功能询问 / 模糊需求
转译目标：形容词换例子 → 封闭式二选一收敛 → 区分 bug 还是需求变更。

三步，每步最多一轮对话（人话示例）：
1. **要例子**："你上次遇到的时候啥情况？哪个页面点的？"
2. **二选一**："是点了没反应，还是有反应但不对？"
3. **定性**：对方说"应该能 XX"——是需求变更，接一句"你是想让它以后能 XX，对吧？现在差哪一块？"；对方只是困惑——直接解释即可，别往需求上拐。

## 输出格式（严格遵守）

```
【卡片】（这个给你自己看的，不发微信）
场景：bug
原话：（原消息）
已确认：
  - 位置：...
  - 现象：...
  - 期望：...
待确认：
  - ...（不脑补，只列缺口）

【话术】（复制进微信，2-3 条短气泡，每条一行，不带任何符号；带逻辑链：复述→猜想→提问）
这个大概知道哪的问题，列表还是旧的、详情页是新值？
截两张图发我，我看下是缓存没刷还是数据没存上
顺带问下，一直这样还是这两天才这样？

【回写】（所有槽位确认完、锁定边界时发，填成具体词不带【】，一句话收拢因果）
对一下啊：就是列表页电话没跟着改、详情页正常，你希望保存后两边一致，我按这个查，对吧
```

注意：卡片是给你自己看的结构，不发微信；话术和回写会发进微信，这两处必须人话。

## 验证记录（可选：持续优化模板用）
每次真实使用，追加一行到验证记录表（templates/verify-log.md 拷到你的工作目录）：
- 日期 | 场景 | 原话（脱敏） | 几轮问满槽位 | 对方是否顺着给了信息 | 话术被嫌烦了吗 | 结果

模板里的追问示例是假设，**以验证记录回填为准**：永远填不满的槽位 → 内置追问逻辑；一句话就填上的 → 从模板删掉；被嫌烦的句式 → 换语气重写并加进禁用词表。
